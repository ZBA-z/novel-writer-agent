# 项目文件结构与状态管理（Project Structure & State Management）

> 用途：长篇小说的项目文件结构、状态追踪、上下文管理，防止写到几十章后人设崩/伏笔丢/时间线乱。
> 核心原则：用文件系统管理记忆，不靠对话上下文硬撑。对话只负责创作，记忆交给文件。

---

## 一、什么时候需要建项目

- 超过10章的长篇 → 必须建项目
- 10章以内的短篇 → 可以用单个文件，但必须包含人物表和细纲
- 用户说"写一本小说"/"写长篇"/"写XX万字" → 必须建项目

---

## 二、项目文件结构

```
{书名}/
├── 设定/
│   ├── 世界观.md          # 背景/力量体系/地理/势力/规则
│   ├── 人物表.md          # 所有主要角色的人物表（或按角色拆文件）
│   ├── 关系.md            # 角色关系映射
│   └── 题材定位.md        # 核心梗+对标分析+写法基因（蒸馏结果）
├── 大纲/
│   ├── 全书大纲.md        # 卷级结构+主线+人物弧线+伏笔总表
│   ├── 卷纲_第一卷.md     # 每卷章节规划+爽点节奏+情绪曲线
│   └── 细纲/              # 每章一个细纲文件
│       ├── 第001章.md
│       ├── 第002章.md
│       └── ...
├── 正文/
│   ├── 第001章_章名.md
│   ├── 第002章_章名.md
│   └── ...
└── 追踪/
    ├── 角色状态.md        # 每个角色当前状态快照（每章更新）
    ├── 伏笔.md            # 伏笔埋设/回收状态表
    ├── 时间线.md          # 故事内时间线
    └── 上下文摘要.md      # 最近3-5章摘要（写新章时读取）
```

## 三、各文件模板与使用规则

### 3.1 世界观.md
```
【世界观】

1. 基本设定
   - 时代/背景：[架空/未来/古代/现代]
   - 地理：[主要地点/地图描述]
   - 社会结构：[势力分布/等级制度/经济体系]

2. 力量体系
   - 等级划分：[从低到高]
   - 每级能力边界：[能做什么/不能做什么]
   - 升级条件：[怎么升级/需要什么资源]
   - 能力代价：[使用能力有什么代价]

3. 核心规则（什么是不可能的）
   - [规则1]：这个世界绝对不会发生的事
   - [规则2]：...
   （这是世界观合同，写作时不能违反）

4. 重要组织/势力
   - [势力名]：[立场/实力/目标/和主角的关系]

5. 特殊设定
   - [金手指/系统/特殊物品的规则]
```

**使用规则**：写作前读取。正文不能违反世界观规则。如果需要新增设定，先更新此文件再写正文。

### 3.2 人物表.md
按 `character-bible.md` 的模板，每个主要角色一个完整人物表。角色多时可拆分为 `人物/角色名.md`。

**使用规则**：写某角色出场的章节前必须读取该角色的人物表。角色状态变化后更新"当前状态快照"。

### 3.3 全书大纲.md / 卷纲_第X卷.md
按 `outline-architecture.md` 的模板。

**使用规则**：写新章节前读取对应卷纲和细纲。大纲可以调整，但调整后必须更新文件并记录调整原因。

### 3.4 细纲/第XXX章.md
按 `outline-architecture.md` 的章细纲模板。每章一个文件。

**使用规则**：写正文前必须读取本章细纲。正文可以和细纲有出入（写作中灵感变化），但出入较大时必须更新细纲文件。

### 3.5 正文/第XXX章_章名.md
```
第X章：章名

[正文内容，2000-2500字]

---
【本章元数据】
- 字数：XXX字
- 完成日期：YYYY-MM-DD
- 打磨轮次：X轮
- 审稿评分：XX/100
- 本章伏笔：埋设[X]/回收[X]
- 本章角色状态变化：[角色A从X变为Y]
```

### 3.6 追踪/角色状态.md
```
【角色状态快照】
最后更新：第X章

| 角色 | 当前位置 | 身体状态 | 心理状态 | 持有物品 | 已知信息 |
|------|----------|----------|----------|----------|----------|
| 主角 | [在哪] | [健康/受伤/...] | [情绪/想法] | [关键道具] | [知道什么] |
| 角色A | ... | ... | ... | ... | ... |
```

**更新规则**：每章写完后更新。写新章前读取，确保角色状态和上一章衔接。

### 3.7 追踪/统一伏笔追踪表.md（长篇用升级版）
> 超过30章的长篇必须用升级版伏笔表，简单版管理不了几十上百个伏笔。

```
【统一伏笔追踪表】
最后更新：第X章
总伏笔数：XX个（已回收XX个/已埋设XX个/计划中XX个）

## 分类总览
| 分类 | 数量 | 已回收 | 已埋设 | 计划中 |
|------|------|--------|--------|--------|
| 核心主线 | X | X | X | X |
| 角色线 | X | X | X | X |
| 世界观 | X | X | X | X |
| 中期剧情 | X | X | X | X |

## 伏笔明细表
| 编号 | 分类 | 优先级 | 伏笔描述 | 埋设章 | 预计回收 | 实际回收 | 状态 | 关联卷 |
|------|------|--------|----------|--------|----------|----------|------|--------|
| F001 | 核心主线 | 高 | [伏笔内容] | 第3章 | 第15章 | 第15章 | 已回收 | 第1-2卷 |
| F002 | 角色线 | 中 | [伏笔内容] | 第5章 | 第30章 | - | 已埋设 | 第1卷 |

## 跨卷分布表
| 卷 | 本章埋设 | 本章回收 | 活跃伏笔数 |
|----|----------|----------|------------|
| 第1卷 | F001,F002 | - | 2 |
```

**字段说明**：
- 分类：核心主线/角色线/世界观/中期剧情
- 优先级：高（必须回收）/中（应该回收）/低（可废弃）
- 关联卷：伏笔涉及哪些卷
- 状态：计划中/已埋设/已回收/已废弃（说明原因）

**更新规则**：每章写完后更新。每5章全局审查时检查：
1. 有没有超过预计回收30章以上未回收的高优先级伏笔？
2. 有没有连续3卷没有新伏笔埋设？
3. 已废弃的伏笔是否有合理原因？

### 3.8 追踪/时间线.md
```
【故事时间线】

| 故事内时间 | 章节 | 事件 | 涉及角色 | 地点 |
|------------|------|------|----------|------|
| 第1天 上午 | 第1章 | [事件] | 主角/张三 | 地点A |
| 第1天 下午 | 第2章 | [事件] | 主角 | 地点B |
| 第3天 | 第3-4章 | [事件] | 主角/李四 | 地点C |
```

**更新规则**：每章写完后更新。多线叙事时标注每条线的时间，确保不穿帮。

### 3.9 追踪/上下文摘要.md
```
【最近章节摘要】
最后更新：第X章

第X章：[一句话概括+关键事件+角色状态变化+伏笔操作]
第X-1章：...
第X-2章：...
第X-3章：...
第X-4章：...

【当前主线进度】：[目前推进到哪一步]
【当前活跃冲突】：[当前正在进行的冲突]
【近期需要回收的伏笔】：[F00X/F00Y，预计在第几章回收]
```

**更新规则**：每章写完后更新（只保留最近3-5章，更早的移入时间线）。写新章前必须读取。

## 四、写作前读取清单

写每一章正文前，必须读取：
1. ✅ 本章细纲（`大纲/细纲/第XXX章.md`）
2. ✅ 出场角色人物表（`设定/人物表.md` 或 `设定/人物/角色名.md`）
3. ✅ 前一章正文末尾（`正文/第X-1章_*.md` 的最后200字）
4. ✅ 角色状态快照（`追踪/角色状态.md`）
5. ✅ 伏笔表（`追踪/伏笔.md`，检查本章要埋/收什么）
6. ✅ 上下文摘要（`追踪/上下文摘要.md`）
7. ✅ 世界观（`设定/世界观.md`，涉及设定时）

读完后再动笔。不允许"凭印象写"。

---

## 五、写作后更新清单

每章正文完成并通过审查后，必须更新：
1. ✅ 角色状态快照（`追踪/角色状态.md`）
2. ✅ 伏笔表（`追踪/伏笔.md`，更新埋设/回收状态）
3. ✅ 时间线（`追踪/时间线.md`）
4. ✅ 上下文摘要（`追踪/上下文摘要.md`，加入本章摘要，移除最旧的一章）
5. ✅ 正文文件元数据（字数/评分/伏笔操作）

不更新追踪文件=下一章一定会出问题（状态不衔接/伏笔遗忘/时间线穿帮）。

---

## 六、全局一致性审查（每5章）

每写完5章，执行一次全局审查：
1. 读取全部追踪文件
2. 检查设定一致性（5章内有没有前后矛盾）
3. 检查伏笔（有没有遗忘的/该回收没回收的）
4. 检查人设（角色有没有慢慢偏离人物表）
5. 检查时间线（有没有穿帮）
6. 检查主线进度（5章推进了多少，有没有原地踏步）
7. 发现问题→修正→更新文件→继续

## 八、记忆保障系统（超过30章的长篇必建）
> 核心原则：AI上下文窗口有限，600章细纲不可能全塞进记忆。用文件系统管理记忆，不靠对话上下文硬撑。

### 8.1 新增追踪文件（在基础4个之上）
```
追踪/
├── 项目索引.md          # 一页纸掌握全项目（核心设定+卷结构+所有文件路径+当前进度）
├── 章节写作SOP.md       # 写前5步必读→写作规则→写后4步更新→打磨3轮
├── 新对话恢复指南.md     # 换对话后3步恢复上下文
├── 角色状态.md          # 基础4个之一
├── 统一伏笔追踪表.md     # 升级版伏笔表（分类+跨卷分布+优先级）
├── 时间线.md            # 基础4个之一
└── 上下文摘要.md        # 基础4个之一（含全书进度总览）
```

### 8.2 项目索引.md（一页纸掌握全项目）
```
【项目索引】
1. 基本信息：书名/题材/作者/当前正文进度
2. 核心设定：主角/女主/反派/力量体系/金手指进化/番茄硬标准
3. 全书结构：20卷（或X卷）快速定位表（卷名+章节范围+核心事件）
4. 文件路径：所有设定/大纲/细纲/正文/追踪文件的完整路径
5. 当前状态：正文写到第几章/细纲完成度/待办事项
```
**用途**：新对话中第一个读这个，30秒恢复全貌。

### 8.3 新对话恢复流程（3步，必做）
**第1步：读项目索引**（30秒）——知道写到哪了、文件在哪
**第2步：按任务读对应文件**（2分钟）：
- 写正文→读本章细纲+人物表+上下文摘要+角色状态+前章末尾
- 改细纲→读v2.0全书大纲+对应卷细纲+世界观+人物表
- 优化技能→读SKILL.md+对应references
**第3步：确认状态后开始工作**——输出"当前状态确认"再动手

### 8.4 渐进式读取原则（不塞爆上下文）
- 不读全部600章细纲，只读当前要写的那卷（约4000tokens）
- 不读全部人物表，只关注本章出场角色
- 不读全部伏笔，统一表中查本章涉及的伏笔
- 上下文摘要只保留最近3-5章（约500字）+全书进度总览

### 8.5 写后更新闭环
每章写完后必须更新：角色状态→上下文摘要→伏笔追踪→时间线。
不更新=下一章一定会出问题（状态不衔接/伏笔遗忘/时间线穿帮）。

## 九、多项目管理与存放规则
> 当创作多本小说时，必须按此规则管理，避免项目混乱。

### 9.1 根目录
所有小说项目统一存放在 `{workspace}/小说项目/` 下，每本小说一个独立子文件夹。

### 9.2 文件夹命名
格式：`{书名}_{编号}`
- 书名：最终确定的书名（不是暂定名）
- 编号：两位数字，从01递增
- 示例：`别人逃命我献祭_01`、`我的御兽能进化_02`

### 9.3 项目内部结构（7目录+1文件）
```
{书名}_{编号}/
├── 项目信息.md          # 一页纸掌握项目（书名/作者/题材/进度/核心设定/文件索引）
├── 设定/                # 世界观/人物表/题材定位/书名简介封面
├── 大纲/                # 全书大纲/卷纲（细纲独立目录）
│   └── 归档/            # 旧版大纲
├── 细纲/                # 标题事件/详细细纲（每30章一个文件）
│   └── 归档/            # 旧版细纲
├── 正文/                # 每章正文（第XXX章_章名.md）
├── 审查报告/            # 章节审查/细纲审查
│   ├── 章节审查/
│   └── 细纲审查/
└── 追踪/                # 项目索引/角色状态/伏笔表/时间线/上下文摘要/SOP/恢复指南
    └── 归档/            # 旧版追踪文件
```

### 9.4 版本管理
- 旧版文件移入`归档/`，不删除
- 新版文件标注版本号和修改日期
- 不直接覆盖旧版文件

### 9.5 多项目并行
- 每个项目独立，不跨项目引用
- 写新章节前确认当前在哪个项目目录
- 每个项目有独立的`项目信息.md`和`追踪/项目索引.md`
