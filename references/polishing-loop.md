# 反复打磨循环（Polishing Loop）

> 用途：每章正文初稿完成后，通过"编辑打磨→审稿评分→重写"循环，确保交付质量。最多3轮，3轮不通过标注问题交付人工。
> 核心原则：初稿是毛坯，打磨才是成品。不交付初稿，就像不交付没装修的房子。

---

## 一、打磨循环流程

```
初稿 → 第0轮：朱雀降AI（必做，目标<20%） → 第1轮：编辑打磨 → 第2轮：审稿评分 → 通过？→ 是 → 交付+更新状态
                                                              ↓ 否
                                                           指出具体问题
                                                              ↓
                                                           重写修改
                                                              ↓
                                                           再审稿（最多3轮）
                                                              ↓
                                                        3轮仍不通过 → 标注问题+交付用户人工介入
```
> **第0轮朱雀降AI是硬性前置**：不做降AI的初稿不进入编辑打磨。详见 `references/anti-ai-detection.md`。

---
## 二、第0轮：朱雀降AI（必做，目标AI率<20%）
按 `anti-ai-detection.md` 的"打磨七刀"逐段执行：句子长度重组/AI套话清除/语义连贯破坏/逻辑模式打乱/个人化表达/对话人味化/段落结构去模板。
**验证**：朱雀检测整体<20%且无单段>40%才算通过，不通过不进入第1轮。

## 二、第1轮：编辑打磨

编辑打磨的目标是"把初稿从60分拉到75分"，聚焦可操作的具体修改。

### 2.1 打磨七刀

**第一刀：去水**
- 删掉：开场回顾/寒暄打招呼/走路进门坐下等过场/角色把观众刚看到的事再讲一遍/解释设定的长台词/重复信息/无冲突日常
- 判断法：把这段删掉，主线受影响吗？不受影响→删。受影响但能用一句话交代→压缩。

**第二刀：去AI味**
- 按 `chapter-writing.md` 第7节去AI味检查
- 重点清除：AI套话/均匀句式/总结段落/说教腔/模板化结构
- 改写范例：
  - ❌ "他的眼中闪过一丝惊讶" → ✅ "他愣了一下，手里的茶杯顿在半空"
  - ❌ "不是他不够强，而是敌人太狡猾" → ✅ "他输了。输在没料到对方还有后手。"
  - ❌ "总而言之，这场战斗奠定了他在宗门中的地位" → （直接删掉，让读者自己感受）

**第三刀：调节奏**
- 检查场景数（≤4），超过就合并或删
- 检查爽点位置（应该在后三分之一），太靠前就加铺垫，太靠后就删废话
- 检查段落长度（变化段落长度，不要全是3句一段）
- 检查句子长度（长短交替，不要全是中等句）

**第四刀：加爽点**
- 本章爽点四段式完整吗？（压抑→触发→爆发→余韵）
- 爆发部分够不够"可视化"？（用动作画面，不是嘴说）
- 有没有反应镜头？（旁人震惊/反派变脸——爽感放大器）
- 爽点不够的地方：加一个小反转/加一个信息炸弹/加一个身份暗示

**第五刀：修对话**
- 长台词拆短（≤15字/句）
- 加潜台词（人不会把心里话说全）
- 加角色区分度（每个角色说话方式不同）
- 删反派解释计划（反派不话多）
- 提示语用动作/表情代替"他说""她道"

**第六刀：修衔接**
- 章首和前章末尾衔接自然吗？（位置/时间/情绪/对话）
- 场景之间过渡自然吗？（不是硬切）
- 章尾钩子和下一章细纲的开场衔接吗？

**第七刀：查记忆点**
- 本章出场的每个主要角色，口头禅/行为习惯/小动作至少出现1次了吗？
- 角色的标志性特征（疤痕/配饰/武器）在出场时有提及吗？
- 角色的价值观标签在选择/行为中有体现吗？
- 没有记忆点的角色=工具人，必须补上（但不要硬塞，要自然融入场景）

### 2.2 打磨输出格式
```
【第X章打磨记录】

打磨前字数：XXX字
打磨后字数：XXX字

修改内容：
1. [去水]：删掉了XXX段（原因：XXX）
2. [去AI味]：将"XXX"改为"XXX"（原因：XXX）
3. [节奏]：将场景X和场景Y合并（原因：XXX）
4. [爽点]：在爆发段增加了反应镜头（原因：放大爽感）
5. [对话]：将XXX的长台词拆为3句（原因：≤15字原则）
6. [衔接]：调整了章首开头（原因：与前章衔接更自然）

仍存在的问题：
- [如果有暂时无法解决的问题，标注出来]
```

## 四、第2轮：审稿评分

按 `content-review.md` 八维审查评分，每维0-10分。

### 3.1 评分标准
- **9-10分**：该维度近乎完美，几乎无改进空间
- **7-8分**：该维度良好，有少量改进空间
- **5-6分**：该维度及格，有明显问题需要修改
- **0-4分**：🔴致命问题，必须重写

### 3.2 通过条件
- 综合评分≥7分
- 无任一维度≤4分（🔴致命问题）
- 合规维度必须≥7分（红线零容忍）

### 3.3 审稿报告格式
```
【第X章审稿报告】

综合评分：XX/100（[等级]）

八维得分：
1. 逻辑自洽：XX/10
2. 爽点充足：XX/10
3. 节奏控制：XX/10
4. 人物一致：XX/10
5. 钩子到位：XX/10
6. 去AI味：XX/10
7. 内容合规：XX/10
8. 上下文连贯：XX/10

主要问题（按优先级）：
1. 🔴[致命问题]：[具体描述]→[修改建议]
2. 🟡[需改进]：[具体描述]→[修改建议]
3. 🟢[小优化]：[具体描述]→[修改建议]

审稿结论：[通过/不通过，需重写]
```

## 五、重写策略

审稿不通过时，根据问题类型采取不同重写策略：

### 4.1 🔴致命问题重写
| 问题 | 重写策略 |
|------|----------|
| 机械降神（突然出现没建立过的力量解决问题） | 回到前文埋伏笔，或让主角用已有能力+智慧解决 |
| 人设崩塌（角色言行不符合人物表） | 按人物表重写该角色的所有言行 |
| 设定矛盾（和已建设定冲突） | 修正正文以符合设定，或更新设定文档（但不能为了圆剧情乱改设定） |
| 逻辑断裂（因果链不成立） | 补上缺失的因果环节，或修改事件使其合理 |
| 合规红线 | 删除/替换红线内容，用安全方式呈现 |

### 4.2 🟡需改进修改
| 问题 | 修改策略 |
|------|----------|
| 爽点不足 | 加压抑铺垫/加爆发规模/加反应镜头 |
| 节奏拖沓 | 删过场/合并场景/加快信息释放 |
| 对话AI味 | 按对话规范逐句改写 |
| 钩子弱 | 换更强的钩子类型（见hook-techniques.md） |
| 上下文不连贯 | 调整章首衔接/修正角色状态 |

### 4.3 重写规则
1. **只改问题部分**，不整篇重写（除非🔴问题覆盖全章）
2. **重写后重新审稿**，确认分数提升
3. **最多3轮**，3轮仍不通过→标注所有问题+当前最佳版本→交付用户人工介入
4. **每轮重写都要记录**：改了什么、为什么改、改后效果

---

## 六、打磨效率原则

1. **先大后小**：先解决🔴致命问题和🟡需改进，再处理🟢小优化
2. **一次改一类问题**：不要同时改节奏又改对话又改爽点，改完一类再审一类
3. **不改对的地方**：打磨是修问题，不是重写。写得好的段落保持不动
4. **字数控制**：打磨后字数仍需在2000-2500范围内，删多了补细节，加多了删废话
5. **不要过度打磨**：7.5分就可以交付，追求10分是浪费时间（ diminishing returns）

---

## 七、打磨质量自检

- [ ] 朱雀降AI完成？→ 整体AI率<20%，无单段>40%
- [ ] 编辑打磨七刀都过了一遍？（去水/去AI味/节奏/爽点/对话/衔接/记忆点）
- [ ] 八维审稿评分完成？
- [ ] 综合≥7分？无🔴致命问题？
- [ ] 合规≥7分？
- [ ] 重写后重新审稿了？
- [ ] 打磨记录已保存？
- [ ] 字数仍在2000-2500？
- [ ] 没有把写得好的地方改坏？
