# 每30章批量审查打磨（Batch Review Every 30 Chapters）
> 用途：每生成满30章正文后，自动触发一次跨章节批量审查打磨，以最苛刻角度多元审查，至少找出100个问题并全部解决。
> 核心原则：单章审查抓"这一章好不好"，批量审查抓"这30章放在一起好不好"。单章看不出的问题（节奏断层/人设漂移/伏笔遗忘/AI模式累积/爽点疲劳），批量审查才能抓出来。
> 触发条件：正文累计生成满30章（第30/60/90/120...章）时自动触发，不需要用户提醒。

---

## 一、为什么必须每30章批量审查

### 1.1 单章审查的盲区
单章八维审查只能检查"这一章内部"，但长篇小说的致命问题往往是跨章的：
- **节奏断层**：单章看都有爽点，但30章连起来发现连续10章都是同一种爽点（打脸→打脸→打脸），读者疲劳
- **人设漂移**：每章看角色言行都合理，但30章后主角性格从"谨慎"变成了"莽夫"，自己没察觉
- **伏笔遗忘**：第5章埋了个伏笔，第35章还没回收，单章审查时每章都"忘了检查"
- **AI模式累积**：单章AI率都<20%，但30章连起来发现每章结尾都是同一种钩子结构（危机悬停→危机悬停→危机悬停），整体AI模式暴露
- **爽点密度不均**：前10章爽点密集，后20章全是铺垫，单章看每章都"有爽点"，但整体节奏崩了
- **设定矛盾累积**：第3章说"镇神石只有3块"，第28章又出现第4块，单章审查时没对照前文

### 1.2 30章是最佳审查周期
- 太短（10章）：问题还没累积，审查效率低
- 太长（50章+）：问题太多改不动，修正成本指数级上升
- **30章**：刚好是番茄男频一个"小高潮周期"（约3卷内容/6-7万字），足以暴露跨章问题，修正成本可控

## 二、批量审查硬指标

| 指标 | 标准 | 不达标后果 |
|------|------|-----------|
| 问题数量 | **至少100个**（无论大小） | 不允许说"没发现问题"，必须重新审查 |
| 问题覆盖维度 | 至少覆盖8个维度 | 单维度问题不超过40% |
| 🔴致命问题 | 发现后必须立即修正 | 不允许"先记着以后改" |
| 🟡需改进 | 本轮全部解决 | 不允许遗留到下一批 |
| 🟢小优化 | 至少占30% | 证明审查足够细致 |
| 降AI抽检 | 30章中随机抽3章送朱雀检测 | 任一章>20%则该章重写 |
| 修正后复审 | 所有修正项必须复审确认 | 修正不到位的重新改 |

### 问题数量分配建议（100个）
| 维度 | 目标数量 | 说明 |
|------|---------|------|
| 逻辑自洽 | 15个 | 因果链/能力边界/时间线/设定矛盾 |
| 爽点充足 | 15个 | 爽点重复/爽点不足/四段不完整/无反应镜头 |
| 节奏控制 | 12个 | 场景过多/过场水戏/字数偏差/节奏断层 |
| 人物一致 | 12个 | OOC/口头禅缺失/角色区分度/反派降智 |
| 钩子到位 | 10个 | 钩子类型重复/假钩子/钩子无回应 |
| 去AI味 | 15个 | AI套话/句式均匀/模板化结构/对话工整 |
| 内容合规 | 5个 | 敏感词/血腥过度/政治风险 |
| 上下文连贯 | 10个 | 前后矛盾/伏笔断线/角色状态不延续 |
| 跨章结构 | 6个 | 卷节奏/情绪曲线/爽点分布/信息释放 |
| **合计** | **100个** | |

## 三、批量审查执行流程（三轮法）

### 第一轮：逐章扫描（找"点"的问题）
**目标**：逐章检查，找出每章内部的具体问题。
**方法**：
1. 从第1章（或本批次第1章）开始，逐章读取正文
2. 每章按八维审查快速过一遍，重点找：
   - AI套话（"眼中闪过一丝""嘴角勾起一抹"等）
   - 字数不达标（<2000或>2500）
   - 场景数>4
   - 章尾钩子类型重复（连续3章同一种钩子）
   - 角色口头禅/习惯缺失
   - 爽点四段不完整
   - 对话过长（>15字/句）
   - 总结性段落
3. 每章至少找出3-4个问题，30章累计90-120个
4. 记录格式：`第X章 - [维度] - 问题描述 - 位置（段落/句子）`

**注意**：第一轮只记录问题，不修改。全部扫完再统一修改，避免改了前面影响后面判断。

### 第二轮：跨章关联（找"线"的问题）
**目标**：把30章放在一起看，找出跨章的结构性问题。
**方法**：
1. **节奏线**：画出30章的爽点分布曲线（每章爽点数量/类型/强度），检查：
   - 是否有连续3章以上无大爽点？
   - 爽点类型是否重复（连续打脸/连续升级）？
   - 情绪曲线是否有起伏（不是一直高或一直低）？
   - 卷末高潮是否到位？
2. **人设线**：检查主角和主要配角在30章内的言行变化：
   - 主角性格是否漂移？（从谨慎变莽/从冷静变冲动）
   - 角色口头禅是否持续使用？（每章出场至少1次）
   - 角色关系是否有逻辑演变？（不是突然变好/变坏）
   - 反派是否降智？（前期聪明后期蠢）
3. **伏布线**：对照伏笔追踪表，检查：
   - 已埋设的伏笔是否在预计章节回收？
   - 有没有"埋了就忘"的伏笔？
   - 有没有"突然回收"但前文没埋过的伏笔？
   - 伏笔密度是否合理（不是全堆在开头或结尾）？
4. **设定线**：检查30章内的设定一致性：
   - 力量等级是否前后一致？
   - 道具数量/位置是否矛盾？
   - 地理/时间线是否穿帮？
   - 有没有"临时加设定"的机械降神？
5. **AI模式线**：检查30章的整体AI特征：
   - 章首开头方式是否重复？（连续5章都是"XX推开了门"）
   - 章尾钩子类型是否重复？
   - 战斗场景写法是否模板化？
   - 对话提示语是否均匀（"他说""她道"交替）？
   - 段落结构是否都是"总起→展开→小结"？

### 第三轮：全局体验（找"面"的问题）
**目标**：以全新读者视角，模拟连续阅读30章的体验。
**方法**：
1. **全新读者视角**：假装完全不了解故事，从第1章开始连续"读"（快速浏览+关键章节细读）
2. 检查：
   - 前3章能不能抓住人？（黄金三章标准）
   - 第10章左右会不会想弃书？（第一个疲劳点）
   - 第20章左右有没有大高潮？（第二个疲劳点前必须有爽点）
   - 第30章结尾有没有足够的追更动力？
   - 世界观是否在30章内逐步清晰？（不是一开始全讲也不是一直不讲）
   - 主角目标是否明确？（读者知道主角在干什么、为什么干）
   - 有没有"读了10章还不知道在讲什么"的问题？
3. **信息差检查**：
   - 读者知道但角色不知道的信息（制造期待）
   - 角色知道但读者不知道的信息（制造悬念）
   - 读者和角色都不知道的信息（制造困惑=坏）
   - 作者以为讲了但读者没get到的信息（信息差漏洞）

## 四、问题分类与解决策略

### 4.1 🔴致命问题（必须立即修正，不允许遗留）
| 问题类型 | 解决策略 |
|---------|---------|
| 机械降神（突然出现新能力/新道具解决问题） | 回到前文埋伏笔，或让主角用已有能力+智慧解决 |
| 人设崩塌（角色言行严重不符合人物表） | 按人物表重写该角色相关段落 |
| 设定矛盾（前后设定冲突） | 修正正文以符合设定文档，或更新设定文档（但不能为了圆剧情乱改设定） |
| 逻辑断裂（因果链不成立） | 补上缺失的因果环节，或修改事件使其合理 |
| 合规红线（政治/色情/血腥过度） | 删除/替换，用安全方式呈现 |
| 朱雀AI率>20%（抽检章节） | 按anti-ai-detection.md打磨七刀逐段降AI，重测直到<20% |

### 4.2 🟡需改进（本轮全部解决）
| 问题类型 | 解决策略 |
|---------|---------|
| 爽点不足/重复 | 加压抑铺垫/换爽点类型/加反应镜头/加小反转 |
| 节奏拖沓/断层 | 删过场/合并场景/加快信息释放/调整章间节奏 |
| 对话AI味/不自然 | 按对话规范逐句改写，加废话/打断/沉默/潜台词 |
| 钩子弱/重复 | 换更强的钩子类型（13式轮换），确保钩子紧扣主线 |
| 上下文不连贯 | 调整章首衔接/修正角色状态/补伏笔呼应 |
| 字数不达标 | 不足补细节（动作/环境/反应），超了删废话/过场 |
| 伏笔遗忘 | 在合适章节回收，或标注"延期回收"并说明原因 |
| 角色区分度低 | 给每个角色加独特用词/口头禅/行为习惯 |

### 4.3 🟢小优化（至少占30%，证明审查细致）
| 问题类型 | 解决策略 |
|---------|---------|
| 个别AI套话 | 替换为具体动作/对话/细节 |
| 句式均匀 | 长短句交替，加1字句段落 |
| 段落开头重复 | 变化开头方式（对话/动作/环境/时间） |
| 提示语单调 | 用动作/表情代替"他说""她道" |
| 个别用词不准确 | 替换为更精准的词 |
| 标点/格式小问题 | 修正 |
| 记忆点缺失 | 自然融入角色口头禅/习惯 |
| 环境描写不足 | 加1-2个氛围感细节 |

## 五、批量降AI处理方法

### 5.1 批量AI套话扫描
对30章全文执行以下关键词扫描（用Grep工具），每发现一处记录为一个问题：
- "眼中闪过一丝" / "眼中闪过"
- "嘴角勾起一抹" / "嘴角勾起"
- "空气仿佛凝固" / "时间仿佛静止"
- "不是X而是Y" 句式
- "众所周知" / "值得一提的是" / "不得不说" / "总而言之" / "综上所述"
- "最终" / "终于" / "显然" / "毫无疑问"
- "他的心中涌起" / "一股复杂的情感"
- "与此同时" / "另一边"（转场词滥用）

### 5.2 批量句式检查
- 统计每章的句子长度分布，找出连续3句以上长度相近（差<5字）的段落
- 统计每章的1字句段落数量，<3个的需要补充
- 检查是否有连续3章以上章首开头方式相同

### 5.3 批量钩子类型检查
- 列出30章的章尾钩子类型，检查是否有连续3章以上同类型
- 检查钩子是否都在下一章前500字内有回应

### 5.4 朱雀抽检
- 从30章中随机抽取3章（建议抽第10/20/30章，覆盖前中后）
- 送朱雀AI检测，记录AI率
- 任一章>20%，该章按打磨七刀重写后重测
- 3章都<20%则本批次降AI达标

## 七、与单章审查的区别

| 维度 | 单章八维审查 | 30章批量审查 |
|------|------------|------------|
| 范围 | 1章 | 30章 |
| 重点 | 章内质量 | 跨章一致性+整体节奏 |
| 问题数量 | 每章5-10个 | 至少100个 |
| 降AI | 每章打磨七刀 | 批量套话扫描+3章抽检 |
| 视角 | 作者视角 | 作者视角+全新读者视角 |
| 触发 | 每章写完后 | 每满30章自动触发 |
| 输出 | 审稿评分 | 批量审查报告+全部修正 |

**两者关系**：单章审查是"日常体检"，批量审查是"年度全面体检"。单章审查不能替代批量审查，批量审查也不能替代单章审查。

## 八、执行注意事项

1. **先全部扫描，再统一修改**：不要边扫边改，改了前面会影响后面的判断
2. **问题必须具体**：不允许写"第X章节奏有问题"，必须写"第X章第3段场景切换太突兀，缺少过渡"
3. **100个是下限不是上限**：如果审查细致，通常能找到120-150个问题。找不到100个说明审查不够苛刻
4. **修正后必须复审**：每个问题修正后，确认修正到位，不允许"改了但没改好"
5. **修正不引入新问题**：改A问题时不能破坏B，改完后快速检查上下文
6. **降AI是重点**：30章累积的AI模式是批量审查的核心抓点，必须花至少30%的精力在去AI上
7. **用户偏好优先**：如果用户对某些问题有不同看法（如"这个伏笔我想留到更后面"），尊重用户决定，但记录为"用户决策"
8. **诚实报告**：如果确实找不到100个问题（极罕见），如实说明"本批次质量较高，仅找到XX个问题"，不编造问题
